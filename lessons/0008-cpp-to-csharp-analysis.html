Lesson 0008

C++ 采完之后，C# 怎么分析？

专练交接：磁盘上的 JSONL → 翻译 → 配对 → 报告。 速查：C# 分析。

先钉死一件事

C# 不进入 C++ 进程，也不读进程内分配表。 唯一交接物是 JSONL 文件（ JSON Lines）。

C++：拦截 → 写 alloc/free → 结束写 summary
↓ 文件路径
C#：翻译事件 → live 配对 → 打印报告 + 退出码

CLI 门面

dotnet run --project src/LeakDetector.CLI -- analyze testdata/sample_events.jsonl
  1. 校验参数与文件
  2. 拿到分析报告
  3. 打印；按泄漏计数设退出码

串联细节见 Analyzers / CLI 源码。

翻译 vs 判断

  • Parsers：行 → 强类型事件；不判泄漏
  • Core：与 C++ 同构的档案卡算法——分配入 live、释放出 live、忽略 summary；剩余 = 确定泄漏
  • Reporters：只展示报告

动手：跟样例走 live

testdata/sample_events.jsonl：alloc + summary（无 free）→ 应剩 1 条泄漏。 点「下一步」观察 live 变化。

即使改 summary 的 leak_count，分析结论仍只看 live。summary 是旁证，不是裁判。
1.C++ 采完后，C# 靠什么接到数据？
2.分析器遇到 summary 事件时做什么？
3.全部事件处理完后，泄漏是什么？
