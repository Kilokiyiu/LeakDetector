Lesson 0007

现行范围与边界

能说出：已有什么、两层采集为何分开、明确不做什么。 全文：范围与约束。

技能目标

对照 MISSION.md，用现行决策说话——不背施工阶段名。

已有 vs 分层

已有：插桩账本 + JSONL + C# 管线 → 确定泄漏
↓ 采集 API 必须分开
观测（若做）：主机/进程指标 → 疑似 / 超阈值
分析 / 报告 / CLI 外壳可复用；不要把两种采集揉成一种 Event。

门面契约（演示）

dotnet run --project src/LeakDetector.CLI -- analyze testdata/sample_events.jsonl
# 退出码 1 = 确定泄漏

dotnet run --project src/LeakDetector.CLI -- analyze testdata/sample_no_leak.jsonl
# 退出码 0 = 无泄漏

完整退出码表：CLI 契约。

1.系统内存指标超阈值时，报告里应怎么说？
2.开系统观测时，最重要的设计约束是？
3.关于图形界面，现行决策是？
学习入口 范围与约束 文档导航 方法到架构
主来源：仓库 MISSION.md 与 docs/dev-roadmap.md。 不清楚就问——说出你对「两层采集」的半句理解。
