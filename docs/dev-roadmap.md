# 范围与约束

对照 [MISSION.md](../MISSION.md)。HTML 速查：[reference/dev-roadmap.html](../reference/dev-roadmap.html)。

本文描述**现行产品范围**：已有什么、边界怎么切、明确不做什么。不写分阶段施工表；排期与任务拆分不入库。

## 已有能力

| 能力 | 说明 |
|------|------|
| 进程插桩 | C++ 拦截 `new`/`delete`，内存表记账，控制台报告 |
| JSONL 交接 | 写出 alloc / free / summary，供 C# 消费 |
| C# 管线 | Parsers → Core 分析 → Reporters → CLI |
| 用语 | 插桩账本结论称**确定泄漏** |

## 现行架构约束

| 约束 | 含义 |
|------|------|
| 两层采集分开 | **进程插桩**与**主机/进程内存观测**不共用一种 Event / 采集 API |
| 外壳可复用 | 分析 / 报告 / CLI 可服务不同采集；采集接口保持可插拔 |
| 用语分开 | 观测侧只说**疑似泄漏 / 超阈值**，不打印插桩式 file:line 当「确定泄漏」 |
| 文档职责 | 文档写架构与契约；实现细节到源码里找 |

## 观测能力（尚未实现时的边界）

若增加系统内存观测，现行决策是：

- 采集与插桩 JSONL **字段契约不同**
- 输出仍可走报告层外壳
- 告警用语保持「疑似 / 超阈值」

## 图形界面

**不做。** CLI + 控制台报告覆盖「能讲清、能跑通」。若只要点选文件看报告，也仅可评估只读查看器，且不得压过契约与分层。

## 明确不做

- 图形操作界面（见上）
- 整机 Agent、分布式、完整 APM
- 反射扫内存当主方案
- 移植 Valgrind 内部实现
- 插桩事件与 OS 指标共用一种「万能 Event」
- 把文档写成变更流水或临时 phase/Slice 施工表
